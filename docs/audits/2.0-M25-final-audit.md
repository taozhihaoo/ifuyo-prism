## 5. Semantic Model

SemanticRelation{kind 八种, source(M23 id), target 五态, dispatch 六类, resolution 五态, confidence, file+range, cross_project}；SemanticDiagnostic{kind: dynamic_invocation/reflection_usage}。Evidence = SourceRange + resolution 标注（§32）。

## 6. Symbol Resolution

三级作用域规则（§三/§61 合规）：同命名空间唯一 → using 命名空间 → 全局唯一（Medium/Probable）；多候选 Ambiguous；零 Unresolved。qualified 后缀精确匹配优先。

## 7. Type Resolution

声明面（base_types/参数/字段 TypeSyntax）原样保留（M23）；解析面：base 名/构造目标名经作用域规则 → 项目内类型 Entity 或 External（§19 Syntax vs Semantic 分离——泛型替换 Unsupported）。

## 8. Call Resolution

invocation_expression 节点级收集（修复：子 match 永远看不到自身——移至 walk 入口）；成员解析 = 包含类型链 + base 链 + **接收者参数/字段声明类型**（§46 用例 `p.TakeDamage(10)` → `Game.Player.TakeDamage` Resolved）；arity 级 overload；dynamic 接收者 ⇒ 诊断 + 不建边（§18）。

## 9. Inheritance / Interface / Override

base_list grammar **非 field**（node-types.json 实测——两处抽取修复）；首 base 类 ⇒ INHERITS，interface ⇒ IMPLEMENTS，External ⇒ ReferencesType+External 如实；override 修饰 + base 链同名同 arity、**排除自身声明** ⇒ OVERRIDES。

## 10. Generic Resolution
